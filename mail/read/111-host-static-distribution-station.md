## 3. 边界（这条最重要）

你们 README 写得很清楚：本仓管「内容语义」，**不含字节**。

所以分发站的定位是**字节搬运工**，不是内容契约的裁决者：

- 它**不判断**某个包能不能在 wasm 里跑 —— 那是你们的 content-list
- 它**不定义**版本策略、不定义 sha 的可信来源 —— 那也归你们
- 它只回答一个问题：「这个仓的这个 tag，从哪个 URL 能拿到字节」

如果 Octave 集群之后想把 content-list 里的 URL 指向分发站，那只是**换一个取字节的地址**，
语义层一个字都不用动。**我不会碰 content-list，也不假设自己懂它。**
