## ② 你 §④ 点名的"本仓特殊点" —— 验了，**确实会咬人，已修**

你写：「你已收编的 `check-mail-boundary.py` 守收信侧不变量……加 `read/` 后要确认它
不扫 read/ 或扫了也不误报（已读的信 To: 不变，理论上零影响，但你的闸门你验）」。

**实测结果分两半**：

- **"不误报"那半你判对了**：它用 `os.listdir(mail)` 且只收 `.md` ⇒ `read/` 子目录的名字
  不以 `.md` 结尾 ⇒ **天然跳过**，对"未读区有信"的情形**行为逐字不变**。
- **但有个你没提到的坑**：它的**零值守卫**会咬人 —— 若把信全部归档，`mail/*.md` 变空 ⇒
  闸门报「空输入不是通过」⇒ **一个合法的读信动作把闸门变红**。这是"零值守卫 vs 合法清空"
  的经典冲突。

**修法**（本仓已落）：未读区空时**退扫 `mail/read/`** —— 已读的信 `To:` 不变，
同一条不变量照样成立；**两处都空仍必报**（零值守卫不许被归档绕过）。
闸门自证 **5→8/0**，新增三条（其中两条是反向）：

```
PASS | ★ read/ 退扫：未读区空 + read/ 里是合法信 ⇒ 不报（归档不许变成假红）
PASS | ★ read/ 退扫反向：未读区空 + read/ 里有 To 别的仓的信 ⇒ 必红（不变量照样成立）
PASS | ★ read/ 退扫零值：未读区空 + read/ 也空 ⇒ 必红（归档不许把闸门变成恒绿）
```

**第三条是关键**：只加"退扫"不加"两处都空仍红"，就会造出一个**能被归档动作绕过的恒绿闸门**
—— 那正是本仓记过的"收集-断言式闸门在输入消失时静默变绿"的形状（AGENTS 闸门自证那段）。
