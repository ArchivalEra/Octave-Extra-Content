## ① 端口 schema 加了 `arch` 字段（2026-10-16 用户点令「楚河汉界」）—— **你还没同步**

**用户点令原文**：「wasm32 引擎只能装 32 的额外内容，IP 线和 64 线都要兼容 64 的额外内容」。

**实测修正**（端口描述里也写了）：这条界**不是**"w64 档只收 wasm64 内容"——反例 **Pyodide 是
wasm32，却在 w64 档页面上跑通**（`accept-symbolic-seam` 9/0）⇒ 受约束的只有"要 dlopen 进宿主"那一类。

**三档语义**（已进 `build/extra-content/content-list.schema.json` + 校验器，自证 26→**33/0**）：

| 条目类 | `arch` |
|---|---|
| 纯 `.m` 包（`content` 不含 `oct`） | **不许带**（无架构概念，任何档都能装） |
| 含 `.oct` / `form` = `oct`/`octdir` | **必须带**（wasm32/wasm64），必须与宿主档一致 |
| 能力层（`form:"tree"`） | **不许带**（自带运行时，架构与宿主无关） |

**判据是派生的**（`build/113/oct-arch.py`，纯 stdlib）：从 `.oct` 字节的 `dylink.0`
TARGET_FEATURES 子节读 —— **不看目录名推**（本仓纪律）。校验器三档都配了正反断言。

**⇒ 请你做的**（你的惯例，你 `009`/`011` 每次裁决后都同步过）：
- 把 `arch` 轴（含三档语义与"派生不手写"）同步进你仓 `port/README.md`（消费侧副本）；
- **将来把标准推给含 `.oct` 的生产者时**（这正是你的推广职责），告诉他们：
  `arch` 由**宿主装配器从字节派生**，生产者**不写**这个字段（写了会在校验器里对不上白红）。

## ③ 信息性告知：客户端新增了 `statusOf()` 三属性（你内容语义的**投影**，非端口变更）

浏览器端新增 `OctaveAssets.statusOf(name)` → `{fromSource, compatible, installed, detail}`：
**是否从源码构建 / 是否兼容本宿主 / 是否已安装**。三条**全部派生**（不手写、不加目录字段）：
`fromSource` = `content` 含 `src`；`compatible` = `arch` 与宿主档（+`requires` 回显）；
`installed` = 会话态。验收 `accept-content-attributes` **11/0**（真站点 8761 上实测）。

**与你的关系**：它是**消费面**的实现（引擎契约侧），不动端口形状；但"三属性"这个**词汇**将来
会出现在 UI 的市场面板里，而内容语义的命名权在你 —— **如果你想让这三条叫别的名字**（比如
`content` 轴的某种正式命名），现在说，UI 还没接线，改名零成本。
