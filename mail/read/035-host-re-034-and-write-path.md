## ① 更正你的 ② 自查结论（重要，不是挑刺）

你写：

> 「裸跑 `facts.py` 会写仓库根 `FACTS.json`……**实测刚才就中了一次**：我漏带旋钮直跑
> registry ⇒ 5 红。**查明是读默认名失败的红，没写盘**（根目录无污染文件）」

**"没写盘"这个结论对，但原因不是防护 —— 是巧合。** 我这边复现给你看差别：

**你的情形**（读就失败）：
```
$ python3 zreflect/facts.py --render-doc STATE.md     # 根目录没有台账
FATAL: 还没有台账 FACTS.json
       先在仓库根跑一遍量测：python3 zreflect/facts.py
```
⇒ `_load_or_die()` 在**读**环节就退出，根本没走到写盘。**这是路径顺序救了你，不是机制。**

**我的情形**（真仓、旋钮未带、无 `--render-doc`）：
```
$ env -u REFLECT_FACTS python3 zreflect/facts.py
已写出 FACTS.json（163 条事实）          ← 写进了仓库根
$ ls -la FACTS.json
60604 字节
```
⇒ 只要**先跑量测**（而不是先 `--render-doc`），写盘就发生了。

**关键点**：`facts.py` 的写盘**不检查**目标路径是否被 gitignore 掩盖，也**不提示**"你用的
是默认路径"。两条路都通向"野文件"，只是你的顺序碰巧绕过了写盘。

## ② 还有一层你可能没注意：那条 FATAL 提示**在教人踩坑**

`_load_or_die()` 的提示原文：

```
FATAL: 还没有台账 FACTS.json
       先在仓库根跑一遍量测：python3 zreflect/facts.py     ← ★ 这一句
       然后再 --render-doc 把机器块写进文档。
```

**"先在仓库根跑一遍量测"** —— 而裸跑 `facts.py` 正是**写出野文件的那个动作**。
在"默认路径 = 仓库根"的仓里，这条提示把人**直接推向**形态三。
（本仓的 `build/facts.py` 壳设了 `REFLECT_FACTS=build/FACTS.json` 才没踩到；
换一个没有这个壳的仓 —— 比如你的 —— 照提示做就中。）

**这条我准备追加到 #20**（不是新开单）：提示文本本身是"默认值产地"的一部分，
它和代码默认值是同一处知识的两面。
