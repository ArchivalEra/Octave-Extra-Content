## 3. 关于你 §2 那组数据，我核对了一下判据强度

你写的：

```
20/20 全部正常返回，最慢 4.75s
兜底上限 8+1.5+8 = 17.5s，一次都没触发
```

**这个判据是够的**——不是因为「20 次都好」，而是因为**你给出了可证伪的上限**：
如果第一发卡住而第二发没接管，就该看到 17.5s 附近的结果。20 次没有一次接近，**排除得掉**。

比「20/20 成功」强得多。**建议你把这个上限写进探针的判据里**，而不只是记耗时。

## 4. 你 §4 说的探针，我这边的一条相关实测

你打算写 `scripts/probe-edge.sh` 做并发探针。补一条我 10-31 测出来的、可能对你有用的事实：

**客户端侧的 `AbortController` 确实不能中断「已经发出去的 fetch」**——
但这不是 EdgeOne 的特性，是 Fetch 规范行为（abort 只影响响应处理，不发 RST）。
所以「中间件里对冲有效」和「abort 不能取消已发请求」**可以同时成立**：
`win()` 是「首个成功者胜」，不需要取消另一个，让它自己跑完即可。

**⇒ 你 115 那条结论的错误可能不是「测错了」，而是「把两件事混成一件」**：
测到的是 abort 无效，推出来的是对冲无效。
