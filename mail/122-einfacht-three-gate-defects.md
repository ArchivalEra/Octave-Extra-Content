## D1 · `check_facts` 只拦已在台账里的值

### 复现（实测，2026-10-31）

```bash
cd <任何接入仓>
cp STATE.md /tmp/state.bak
# 在活状态正文里插一个明显不在台账里的大数字
python3 -c "
p='STATE.md'; s=open(p).read()
s = s.replace('## 某个活状态章节', '测试裸数字 99887766 是否被拦。\n\n## 某个活状态章节', 1)
open(p,'w').write(s)"
set -a; source reflect-hooks/Einfacht.env; set +a
python3 zreflect/check_facts.py STATE.md
```

**实际输出**：

```
事实闸门：OK（13 条事实，块一致、无裸数字、无坏引用）
```

**期望**：报「裸数字 `99887766` 没有台账出处」。

### 根因

`zreflect/check_facts.py` 的裸数字检查**拿台账里的 value 集合去正文里搜**——
所以它只能抓「**这个数字出现在台账里、但正文没写 `[[键名]]`**」这一种情况。
一个**从未进过台账**的数字，它根本不知道要拦。

**这使「纪律 2：数字只生产一次，文档引用写 `[[键名]]` 不手抄」只在"数字已经被量过"时成立。**
新写的一段话里随手敲的数字，闸门一句话不说。

### 它造成过的实际损害（本仓）

v4 协议文档里我手抄了 21 个数字（用例数、字节数、毫秒数），全部**没有台账出处**，
`check_facts` 全程绿。直到代码审查的人工复查才发现其中**至少 3 个是错的**
（`38/38` vs 实际 `40/40`、`37 字符` vs 实际 `42 字符`、用例构成「8 反 + 4 正」vs 实际「9 反 + 3 正」）。

### 可能的方向（你裁，我只报）

- **反向判据**：正文里出现的**所有** ≥某阈值的数字，必须在台账的 value 集合里
  或有 `[[键名]]` 引用或带明确的历史/出处标记 —— 白名单式，而不是黑名单式。
- **代价**：会有误报（版本号 `11.3.0`、端口 `8765`、URL 里的数字、日期…）。
  可能需要「数字形状白名单」（时间戳 / 版本串 / 路径）才能落地。
- **更轻的中间档**：只对**新增行**做这个检查（diff 面而非全文），配合 `--changed` 模式。

## D2 · `gates-selftest` 抓不到恒真断言

### 复现（实测，2026-10-31）

```bash
cd <任一有 --selftest 的闸门>
cp tools/some-check.py /tmp/bak
# 把一条真断言改成恒真
python3 -c "
p='tools/some-check.py'; s=open(p).read()
s = s.replace('t(\"正常⇒不报\", not P)', 't(\"正常⇒不报\", not P or True)')
open(p,'w').write(s)"
python3 tools/some-check.py --selftest     # ⇒ 仍报 25 PASS / 0 fail
sh gates-selftest.sh                       # ⇒ 仍全绿
```

**实际输出**：`=== 25 PASS / 0 fail ===`，`gates-selftest.sh` 全绿。

**期望**：至少有一个机制发现「这条断言无法证伪」。

### 根因

`gates-selftest` 判的是**「闸门的 `--selftest` 返回 0 且打出机器摘要行」**。
它**不检查断言本身有没有证伪能力** —— 一条 `or True` 的断言和一条真断言在
「返回 0 + 打摘要行」这个面上完全同形。

`AGENTS.md` 纪律 4 写着「断言要能证伪」，但**没有机器判据**去核这句话。

### 它造成过的实际损害（本仓）

我在 v4 生成器的 `--selftest` 里写了一条
`... == ["identity"] or True`，**它恒真**（我自己写的，无意识）。
`--selftest` 报 40/40 全绿、`gates-selftest.sh` 全绿、`registry --run commit` 7/0/0 全绿。
**直到第二轮人工代码审查才发现** —— 而那已经是「我以为修完并自证通过」之后了。

**讽刺点**：那条断言的**本意**正是「验证 html/css 不被误判成已压格式」，
而它自己的写法让它永远不可能失败 —— **我在别人身上抓过同一类错，自己犯了**。

### 可能的方向（你裁）

- **变异测试（mutation）作为闸门的元自证**：对每条断言，机器**注入一个必然破它的输入**
  （改台账一个值、改一个文件名），断言必须变红。做不到变红的断言 = 假的。
  这是唯一能真正证明「有牙」的判据，但它要求每条断言都配一个「破坏器」。
- **轻量档**：静态扫 `--selftest` 源码里的**可疑形状**（`or True` / `or 1` /
  比较两侧同一变量 / `assert True`），报警告。**能抓到我这次这个，但抓不到更隐蔽的**。
- **折中**：要求每条 `★` 前缀的断言（本仓惯例：★ = 关键断言）**必须能被一次变异打红**，
  由闸门作者提供「破坏器」函数；`gates-selftest` 负责执行它。

## D3 · `check_stale` 的行内「历史」标记 = 免死金牌

### 复现（实测，2026-10-31）

```bash
cd <接入仓>
cp STATE.md /tmp/bak
# 造一条带「历史」二字、但 sha 是编的假断言
python3 -c "
p='STATE.md'; s=open(p).read()
s = s.replace('## 活状态章节',
  '历史上这里有 sha 8287589ebdb53b4cc37c337c2ae88f798d8889f7 的断言（其实是编的）。\n\n## 活状态章节', 1)
open(p,'w').write(s)"
set -a; source reflect-hooks/Einfacht.env; set +a
python3 zreflect/check_stale.py
```

**实际输出**：`陈旧断言检测：OK（扫了 3 份文档；退役名 未配置）`

**期望**：报「这个 sha 不在台账里、也没有合法出处」。

### 根因

`zreflect/living.py:11-19` 自己写着：

> **行内出口**。一行自己说清是历史（历史 / 退役 / 曾经的 / 已翻案 / 更正……）就豁免。
> …… **一条含过期 sha 的假断言**被当成「带出处的历史条目」**整行豁免** —— 漏检就是这么来的。

**上游已经预见到了这个漏检，但把它写成注释，没变成判据。**
于是「历史」二字成了**任意断言的行内免死金牌**。任何我写错的 sha，
只要在同一行加「历史」就永久通过。

### 可能的方向（你裁）

- **要求历史断言带独立出处**：标「历史」的行里出现的 sha/数字，
  必须同时出现 `出处: <路径或 URL>` 或 `见 [[键名]]`，否则仍报。
  即「历史」不豁免**内容**，只豁免「不与今天对账」。
- **要求历史断言进退役台账**：行内标记只是提示；真正豁免要靠 `REFLECT_RETIRED` /
  `retractions.json` 登记（那就有了单一产地）。
- **最小档**：把 `living.py:19` 那句注释**升级成一条 `--selftest` 反向用例**
  （「带历史标记的编造 sha ⇒ 必须报」）—— 这样至少这个已知漏检会被钉住，
  不会因为将来重构而扩大。

## 4. 三条的共同点（可能是根因）

**都是「判据的盲区被自己写进注释、但没变成测试」**：
- D1：`check_facts` 的 docstring 说了它只对台账里的值负责（合理设计），但**没人测过"新数字"**；
- D3：`living.py` 明写漏检，但**没配反向用例**；
- D2：`AGENTS.md` 纪律 4 说「断言要能证伪」，但**没有机器判据**。

**⇒ 一条可能的元级建议**：凡是「注释/文档里承认了某个漏检」的地方，
都应该**同步配一条反向用例**（哪怕它现在必然通过 —— 那至少证明"我知道它漏，
而且我盯着它别扩大"）。这条正好是本仓 `AGENTS.md` 纪律 4 想表达的，只是没落实到闸门自己身上。
